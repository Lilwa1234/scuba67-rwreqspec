# แผนทางเทคนิค: UC02 - ส่งรายการเข้าครัว

## 1. สรุปแนวทาง
1. ฟีเจอร์นี้รองรับการส่งคำสั่งซื้อจากแคชเชียร์ไปยังห้องครัวทันทีหลังยืนยันคำสั่งซื้อผ่าน Local LAN (UC02 Main Flow 1, ASM-01)
2. ระบบจะใช้ Print Queue และ Print Dispatcher เพื่อจัดรูปแบบข้อมูลและส่งไปยัง KDS หรือเครื่องพิมพ์ KOT ตามสถานีเตรียมงานที่กำหนดไว้ (UC02 Main Flow 1-2, ASM-03)
3. พนักงานครัวจะเห็นรายการตามลำดับคิวที่เรียงตามเวลายืนยันและหมายเลขออร์เดอร์เพื่อเตรียมอาหาร (UC02 Main Flow 3, ASM-04)
4. ถ้าเกิดความล้มเหลวในการส่งหรือพิมพ์ ระบบจะแสดงแถบแจ้งเตือนสีแดงและอนุญาตให้กด Reprint KOT เมื่อเชื่อมต่อกลับมาทำงาน (UC02 Alternative 1a, ASM-02, ASM-05)
5. ข้อมูลที่แสดงบน KOT/KDS ต้องระบุเลขออร์เดอร์ ชื่อเมนู และตัวเลือกพิเศษ เพื่อให้ครัวเตรียมอาหารได้ถูกต้อง (UC02 Main Flow 2, ASM-06)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นตาม prompt; spec ไม่ระบุ framework สำหรับ POS หรือหน้าจอครัว |
| Python FastAPI สำหรับหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นตาม prompt; spec ไม่ระบุ framework สำหรับระบบส่งงานครัว |
| ฐานข้อมูล | ทีมเลือกเอง ไม่ได้มาจาก spec | ยังไม่มีข้อจำกัดจาก spec ว่าต้องใช้ระบบจัดเก็บแบบใด |
| Print Queue / Print Dispatcher | ASM-01, ASM-03 | สร้างตามข้อกำหนดในการส่งออร์เดอร์ผ่าน Local LAN และจัด format ตามสถานีเตรียมงาน |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับข้อกำหนด |
|---|---|---|
| Order | orderId, createdAt, confirmedAt, queueSequence, status, kitchenStatus | UC02 Main Flow 1, 3; ASM-01, ASM-04, ASM-05 |
| OrderItem | menuName, modifiers, quantity, stationId, lineStatus | UC02 Main Flow 2-3; ASM-03, ASM-06 |
| KitchenStation | stationId, stationName, printerId, kdsTarget | UC02 Main Flow 2; ASM-03 |
| PrintJob | jobId, orderId, stationId, payload, retryCount, sentAt, status | UC02 Main Flow 1-2, Alternative 1a; ASM-01, ASM-02, ASM-03 |
| ReprintRequest | orderId, reason, requestedAt, completedAt | UC02 Alternative 1a; ASM-02, ASM-05 |

ไม่มีฟิลด์ที่จัดเก็บข้อมูลส่วนบุคคลหรือข้อมูลที่ไม่อยู่ในข้อกำหนดของ UC02; ข้อจำกัดด้านข้อมูล (DOM/IF) ใน spec ยังไม่มีการระบุลักษณะข้อมูลเฉพาะใด ๆ

## 4. API / หน้าจอ

- `POST /api/v1/orders/{orderId}/send-to-kitchen` รับ orderId และ metadata ส่งกลับสถานะการส่งข้อมูลไปยัง Print Queue (UC02 Main Flow 1; ASM-01)
- `GET /api/v1/kitchen/queue` ส่งกลับลิสต์ออร์เดอร์เรียงตามเวลายืนยันและหมายเลขออร์เดอร์ (UC02 Main Flow 3; ASM-04)
- `POST /api/v1/orders/{orderId}/reprint-kot` รับ orderId ส่งกลับสถานะพิมพ์ใหม่เมื่อเชื่อมต่อกลับมาทำงาน (UC02 Alternative 1a; ASM-02, ASM-05)
- `GET /api/v1/orders/{orderId}/kitchen-ticket` ส่งกลับ payload ที่จะพิมพ์หรือแสดงบน KDS รวมเลขออร์เดอร์ เมนู และ modifiers (UC02 Main Flow 2; ASM-06)
- หน้าจอ POS แสดงแถบแจ้งเตือนสีแดงเมื่อส่งหรือพิมพ์ล้มเหลว และให้กด Reprint KOT เมื่อสถานะเชื่อมต่อคืน (UC02 Alternative 1a; ASM-02)
- หน้าจอ KDS แสดงรายการออร์เดอร์ตามคิวและสถานีเตรียมงานที่กำหนด (UC02 Main Flow 2-3; ASM-03, ASM-04)

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี CON ID ใน spec | ไม่มีข้อกำหนดเทคโนโลยีเชิงบังคับที่ต้องใช้ใน plan | ยังไม่ได้ใช้ เพราะ spec ไม่มี CON |
| ไม่มี DOM ID ใน spec | ไม่มีข้อจำกัดด้านข้อมูลหรือโครงสร้างข้อมูลเฉพาะ | ยังไม่ได้ใช้ เพราะ spec ไม่มี DOM |
| ไม่มี IF ID ใน spec | ไม่มีข้อกำหนด interface หรือการเชื่อมต่อระบบภายนอกที่ชัดเจน | ยังไม่ได้ใช้ เพราะ spec ไม่ได้ระบุ IF ชัดเจนสำหรับ KDS/เครื่องพิมพ์หรือภาคเชื่อมต่อ |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| ไม่มี AC ID ใน spec | ยังไม่มีชื่อ test ที่อ้าง AC ได้ | spec ของ UC02 ไม่มี Acceptance Criteria จึงยังไม่สามารถสร้าง test ID ใหม่ได้ โดยจะรอทีมกำหนด AC ให้ชัดก่อนผูกตรวจรับ |

## 7. ลำดับงาน

1. กำหนดโครงสร้างข้อมูลออร์เดอร์และ payload สำหรับ KOT/KDS ให้มีเลขออร์เดอร์ เมนู และ modifiers ครบถ้วน (UC02 Main Flow 2; ASM-06)
2. สร้างฟังก์ชันส่งข้อมูลไปยัง Print Queue ทันทีหลังยืนยันคำสั่งซื้อ และบันทึกเวลาส่ง/สถานะ (UC02 Main Flow 1; ASM-01)
3. สร้าง Print Dispatcher เพื่อจัด Format ตามสถานีเตรียมงาน และเลือกทิศทางส่ง KDS หรือ KOT ตามเงื่อนไข (UC02 Main Flow 2; ASM-03)
4. สร้างหน้า KDS และประมวลผลคิวตามเวลายืนยันและหมายเลขออร์เดอร์ (UC02 Main Flow 3; ASM-04)
5. สร้างการแจ้งเตือนสีแดงและปุ่ม Reprint KOT เมื่อเชื่อมต่อส่งข้อมูลหรือพิมพ์ล้มเหลว (UC02 Alternative 1a; ASM-02, ASM-05)
6. ดำเนินการทดสอบการส่งออร์เดอร์ในไทม์ไลน์ 2 วินาที และตรวจว่าข้อมูลไม่สูญหายเมื่อเกิดความล้มเหลว (UC02 Main Flow 1, Alternative 1a; ASM-01, ASM-02)
7. ทบทวนว่าชุดข้อมูลสรุปใน KOT/KDS ครบถ้วนและสามารถใช้โดยพนักงานครัวได้จริง (UC02 Main Flow 2-3; ASM-06)
8. เมื่อมี AC ที่ชัดเจนจากทีมแล้ว จึงจัดทำ test set สำหรับตรวจรับตาม AC ID เดิมเท่านั้น (ไม่มี AC ID ใน spec ขณะนี้)

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Questions ใน spec ขณะนี้ จึงไม่ต้องคัดลอกคำถามใด ๆ มาไว้ที่นี่

ส่วนที่ยังไม่สร้างจนกว่าจะมีคำตอบเพิ่มเติม:
- กลไกเชื่อมต่อจริงระหว่าง POS กับ KDS/เครื่องพิมพ์ เช่น protocol, endpoint, หรือรูปแบบการส่งข้อมูลที่ใช้อย่างเป็นทางการ
- การกำหนดสถานีเตรียมงานแบบละเอียด เช่น สถานีใดรับเมนูประเภทไหน และต้องจัด format อย่างไร
- การกำหนดการจัดการ retry / queue ที่ครอบคลุมเหตุการณ์เครือข่ายหลุดและกระดาษพิมพ์หมด โดยไม่ได้สร้างสรุปที่ขัดกับ UC02

ส่วนเหล่านี้ยังไม่สร้างจนกว่าทีมจะให้คำตอบเพิ่มเติม เพราะ spec ยังไม่ได้ระบุรายละเอียดเชิง interface หรือเงื่อนไขการทำงานแบบละเอียดมากพอสำหรับการพัฒนาโดยตรง

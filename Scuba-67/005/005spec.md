# Use Case Specification: UC05 - Manage Menu & Modifiers

* **Use Case ID:** UC05[cite: 5]
* **Use Case Name:** จัดการเมนูและราคาตัวเลือก (Manage Menu & Modifiers)[cite: 5]
* **Status:** Draft v2
* **วันที่อัปเดต:** 2026-10-03
* **Actor หลัก:** เจ้าของร้าน / ผู้จัดการ (Owner / Manager)[cite: 5]
* **Pre-condition:** ผู้ใช้งานเข้าสู่ระบบด้วยสิทธิ์ผู้ดูแลระบบ (Admin Role) และมีสิทธิ์เดียวกันเพื่อจัดการเมนูทั้งจากระบบหลังบ้านและบนแอป POS[cite: 5]
* **Post-condition:** ข้อมูลเมนู หมวดหมู่ และราคาตัวเลือกเสริมถูกปรับปรุงในฐานข้อมูล และพร้อมขายหน้าร้านผ่านการซิงก์เรียลไทม์[cite: 5]

## Main Flow (ลำดับขั้นตอนปกติ)
1. เจ้าของร้านเปิดหน้าจอ "จัดการรายการสินค้า" บนระบบหลังบ้านหรือเครื่อง POS โดยต้องเข้าสู่ระบบด้วยสิทธิ์ผู้ดูแลระบบ (Admin Role) เพื่อให้มีสิทธิ์จัดการข้อมูลเมนูในทั้งสองช่องทาง[cite: 5]
2. กำหนดรายละเอียดสินค้า ได้แก่ ชื่อเมนู, หมวดหมู่สินค้า, และราคาเริ่มต้น โดยต้องป้อนข้อมูลผ่าน Single Page Form และตรวจสอบความถูกต้องก่อนกดยืนยันบันทึก[cite: 5]
3. หากเมนูต้องมีตัวเลือกเสริม ให้ผูกกลุ่มตัวเลือกเสริม (Modifier Groups) กับเมนู และกำหนดราคาบวกเพิ่มในหน้าเดียวกัน หากสินค้าที่ไม่มีตัวเลือกเสริม สามารถปล่อยให้ว่างได้[cite: 5]
4. กดยืนยันการบันทึกข้อมูล[cite: 5]
5. ระบบบันทึกข้อมูลเมนูและราคาใหม่ลงฐานข้อมูลผ่าน CRUD API และทำ Instant Sync เพื่อให้อัปเดตบนหน้าจอขายหน้าร้านทันทีโดยไม่ต้อง Restart เครื่อง[cite: 5]

## Alternative / Exception Flows (ขั้นตอนทางเลือก / กรณีข้อผิดพลาด)
* **2a. การลบเมนูถาวร:** หากเมนูเคยมีประวัติการขาย ระบบจะไม่อนุญาตให้ลบออกจากฐานข้อมูลถาวร แต่จะใช้ระบบ Soft Delete โดยเปลี่ยนสถานะเป็น "ซ่อนเมนู" (`is_active = false`) เพื่อไม่ให้กระทบรายงานย้อนหลัง และยังคงมีชื่อเมนูเดิมปรากฏในรายงานย้อนหลัง[cite: 5]
* **5a. การซิงก์ข้อมูลขัดข้อง:** หากการซิงก์ข้อมูลไปยังหน้าจอขายหน้าร้านขัดข้องหรือไม่ตอบสนอง ระบบจะยังคงบันทึกข้อมูลหลักลงฐานข้อมูลผ่าน CRUD API ให้เสร็จสิ้นก่อน เพื่อให้ข้อมูลชุดใหม่พร้อมใช้งานและสามารถดึงไปแสดงผลบนหน้าจอขายเมื่อเชื่อมต่อกลับคืน[cite: 5]

## Assumptions (ข้อสมมติฐานจากคำตอบของทีม)
- **ASM-01:** เมนูที่เคยมีประวัติการขายจะไม่ถูกลบออกจากฐานข้อมูลถาวร แต่จะใช้ Soft Delete โดยเปลี่ยนสถานะเป็น "ซ่อนเมนู" (`is_active = false`) และยังคงมีชื่อเมนูเดิมในรายงานย้อนหลัง (Q1)
- **ASM-02:** Modifier Group ไม่จำเป็นต้องผูกกับทุกเมนู สามารถปล่อยว่างได้สำหรับสินค้าที่ไม่มีตัวเลือกเสริม และหากมีจะผูกได้ในหน้าเดียวพร้อมกำหนดราคาบวกเพิ่ม (Q2)
- **ASM-03:** การซิงก์ข้อมูลเมนูและราคาใหม่ให้หน้าจอขายหน้าร้านเป็น Instant Sync แบบเรียลไทม์ โดยข้อมูลต้องอัปเดตทันทีโดยไม่ต้อง Restart เครื่อง (Q3)
- **ASM-04:** ระบบบังคับให้ระบุชื่อเมนู หมวดหมู่สินค้า ราคาเริ่มต้น และราคาบวกเพิ่มของตัวเลือกเสริมที่ถูกต้องผ่าน Single Page Form ก่อนกดยืนยันบันทึก (Q4)
- **ASM-05:** ผู้ใช้งานต้องเข้าสู่ระบบด้วยสิทธิ์ผู้ดูแลระบบ (Admin Role) เพื่อจัดการเมนูได้ทั้งจากระบบหลังบ้านและบนแอป POS โดยใช้สิทธิ์เดียวกัน (Q5)
- **ASM-06:** การบันทึกข้อมูลหลักจะถูกอัปเดตลงฐานข้อมูลผ่าน CRUD API สำเร็จก่อน เพื่อให้ข้อมูลชุดใหม่พร้อมใช้งานและสามารถดึงไปแสดงผลบนหน้าจอขายหน้าร้านได้ แม้การซิงก์ข้อมูลจะขัดข้องชั่วคราว (Q6)

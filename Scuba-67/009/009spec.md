# Use Case Specification: UC09 - Operate Offline & Sync Data

* **Use Case ID:** UC09[cite: 5]
* **Use Case Name:** ใช้งานโหมดออฟไลน์และซิงก์ข้อมูล (Operate Offline & Sync Data)[cite: 5]
* **Actor หลัก:** แคชเชียร์ (Cashier), ระบบ (System Background Process)[cite: 5]
* **Pre-condition:** สัญญาณอินเทอร์เน็ตของร้านหลุดหรือไม่สามารถเชื่อมต่อคลาวด์ได้[cite: 5]
* **Post-condition:** การขายดำเนินต่อไปได้ และข้อมูลทั้งหมดถูกอัปโหลดขึ้นคลาวด์เมื่อกลับมาออนไลน์[cite: 5]
* **Status:** Draft v2
* **Last Updated:** 2026-10-03

## Main Flow (ลำดับขั้นตอนปกติ)
1. ระบบตรวจพบสัญญาณอินเทอร์เน็ตขาดหาย และสลับเข้าสู่ "Offline Mode" โดยแสดงแถบสถานะสีส้มบนหน้าจอทันทีผ่าน Network Status Monitor[cite: 5]
2. แคชเชียร์สามารถรับออร์เดอร์ คิดเงินสด และสั่งพิมพ์ใบเสร็จได้ตามปกติ โดยในโหมดนี้ระบบรองรับเฉพาะการรับชำระเป็นเงินสดเท่านั้น[cite: 5]
3. ระบบบันทึกข้อมูลธุรกรรมทั้งหมดไว้ใน SQLite หรือ IndexedDB บนเครื่อง POS เป็นแหล่งเก็บข้อมูลหลัก เพื่อให้บันทึกธุรกรรมได้อย่างต่อเนื่องในขณะที่ไม่มีอินเทอร์เน็ต[cite: 5]
4. เมื่อสัญญาณอินเทอร์เน็ตกลับมา ระบบจะทำการซิงก์ข้อมูลขึ้นคลาวด์ในพื้นหลัง (Background Sync) โดยอัตโนมัติ และส่งเฉพาะข้อมูลธุรกรรมและบิลที่ค้างอยู่เท่านั้น ไม่ส่งข้อมูลซ้ำทั้งหมด[cite: 5]
5. ข้อมูลบิลที่ค้างอยู่จะถูกอัปโหลดขึ้นคลาวด์โดยอัตโนมัติภายใน 30 วินาทีหลังกลับมาออนไลน์ และยอดขายรวมบนสมาร์ทโฟนของเจ้าของร้านจะอัปเดตเพิ่มขึ้นตรงกัน 100%[cite: 5]
6. แถบสถานะเปลี่ยนกลับเป็นสีเขียว "Online" และข้อมูลยอดขายบนสมาร์ทโฟนของเจ้าของร้านอัปเดตตรงกันทันที[cite: 5]

## Alternative / Exception Flows (ขั้นตอนทางเลือก / กรณีข้อผิดพลาด)
* **4a. การซิงก์ข้อมูลล้มเหลว:** ระบบจะพยายามส่งข้อมูลซ้ำเป็นระยะ (Auto Retry ทุก 3 นาที) พร้อมแสดงสัญลักษณ์เตือนว่ามีข้อมูลที่ยังไม่ได้อัปโหลดค้างอยู่ และตรวจสอบสถานะการอัปโหลดของแต่ละรายการจนกว่าจะสำเร็จครบถ้วน[cite: 5]

## Assumptions (สมมติฐาน)
* **ASM-01:** ในโหมดออฟไลน์ ร้านจะรองรับเฉพาะการรับชำระเป็นเงินสด แต่ยังสามารถรับออร์เดอร์ คิดเงิน และสั่งพิมพ์ใบเสร็จรับเงินได้ตามปกติ[cite: 5]
* **ASM-02:** ระบบใช้ SQLite หรือ IndexedDB บนเครื่อง POS เป็นแหล่งเก็บข้อมูลหลักเพื่อบันทึกธุรกรรมทั้งหมดไว้ในเครื่องได้อย่างต่อเนื่องระหว่างที่ไม่มีอินเทอร์เน็ต[cite: 5]
* **ASM-03:** ระบบมี Conflict Resolution โดยใช้รหัส UUID ร่วมกับ Timestamp เพื่อป้องกันการเขียนทับหรือเลขออร์เดอร์ชนกันขณะ Reconcile ข้อมูลขึ้นคลาวด์[cite: 5]
* **ASM-04:** เมื่อกลับมาออนไลน์ ระบบจะเริ่ม Background Sync โดยอัตโนมัติและอัปโหลดข้อมูลบิลที่ค้างอยู่ภายใน 30 วินาทีหลังเชื่อมต่อสำเร็จ[cite: 5]
* **ASM-05:** แดชบอร์ดยอดขายบนสมาร์ทโฟนของเจ้าของร้านจะอัปเดตเพิ่มขึ้นตรงกัน 100% หลังข้อมูลถูกอัปโหลดขึ้นคลาวด์สำเร็จ[cite: 5]
* **ASM-06:** ระบบจะแสดงสัญลักษณ์เตือนบนหน้าจอเมื่อมีรายการที่ยังไม่ได้อัปโหลดค้างอยู่ พร้อมสั่งทำงานส่งข้อมูลซ้ำอัตโนมัติ (Auto Retry) ทุก 3 นาที[cite: 5]
* **ASM-07:** การสลับโหมด Online/Offline ทำงานอัตโนมัติผ่าน Network Status Monitor โดยเข้าสู่ Offline Mode ทันทีที่เน็ตหลุด และกลับสู่ Online Mode เมื่อสัญญาณอินเทอร์เน็ตกลับมาเชื่อมต่อได้[cite: 5]
* **ASM-08:** Background Sync จะส่งเฉพาะข้อมูลธุรกรรมและบิลที่ค้างอยู่ในเครื่องหน้าร้านขึ้นคลาวด์ ไม่ได้ส่งข้อมูลซ้ำทั้งหมด และจะตรวจสอบสถานะการอัปโหลดของแต่ละรายการจนกว่าจะสำเร็จครบถ้วน[cite: 5]

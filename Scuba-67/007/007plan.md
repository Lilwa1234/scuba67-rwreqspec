# แผนทางเทคนิค: UC07 - ผูกสูตรและตัดสต๊อกอัตโนมัติ

## 1. สรุปแนวทาง
1. ฟีเจอร์นี้รองรับการผูกสูตรวัตถุดิบกับเมนูสินค้า และเปิด-ปิดการตัดสต๊อกอัตโนมัติแยกรายเมนู โดยเจ้าของร้านหรือผู้จัดการเป็นผู้กำหนดทั้งหมด (UC07 Main Flow 1-4, ASM-02)
2. ระบบจะเก็บข้อมูลสูตรแบบ BOM (Bill of Materials) โดยแต่ละเมนูมีรายการวัตถุดิบและสัดส่วนต่อ 1 หน่วยบริโภค พร้อมอนุญาตให้ใช้หน่วยนับต่างกันในสูตรเดียวกันได้ (UC07 Main Flow 2, ASM-01)
3. เมื่อมีการชำระเงินและปิดบิลสำเร็จ ระบบ Inventory Deduction Engine จะประมวลผลหักสต๊อกแบบ Asynchronous เพื่อหลีกเลี่ยงการบล็อกการขายหลัก (UC07 Main Flow 5, ASM-03, ASM-04)
4. หากสต๊อกคำนวณแล้วติดลบ ระบบจะยังยอมให้ทำรายการขายต่อได้ตามปกติเพื่อความต่อเนื่องหน้าร้าน พร้อมแสดงสัญลักษณ์แจ้งเตือนในรายงาน (UC07 Alternative 5a, ASM-05)
5. โครงสร้างของแผนจะเริ่มจากการกำหนดโมเดลสูตรและสต๊อก ก่อนสร้าง API สำหรับบันทึกสูตรและคำนวณตัดยอด และจัดทำแผนทดสอบเพื่อยืนยันว่าเมนูที่มี BOM คำนวณถูกต้องตามจำนวนสั่งจริง

## 4. API / หน้าจอ

- `GET /api/admin/recipes` ส่งกลับรายการสูตรและเมนูที่ยังมีสถานะใช้งานอยู่เพื่อให้เจ้าของร้านหรือผู้จัดการเลือกเมนูที่ต้องกำหนดสูตร (UC07 Main Flow 1; ASM-02)
- `POST /api/admin/recipes` รับ `menuId`, `items[]`, `autoDeductEnabled` และส่งกลับสูตรที่สร้างใหม่พร้อมคำตอบสำเร็จ (UC07 Main Flow 2-4; ASM-01, ASM-02)
- `PATCH /api/admin/recipes/{recipeId}` รับรายการวัตถุดิบที่ต้องปรับปรุงและสถานะเปิด-ปิดการตัดสต๊อกอัตโนมัติ (UC07 Main Flow 2-4; ASM-01, ASM-02)
- `GET /api/inventory/ingredient-stock` ส่งกลับจำนวนสต็อกปัจจุบันของวัตถุดิบเพื่อใช้ในหน้าจอจัดการสูตรหรือรายงาน (UC07 Main Flow 2; ASM-05)
- `POST /api/orders/{orderId}/deduct-inventory` รับข้อมูล orderId, menuId, quantity และเริ่มงานคำนวณตัดสต๊อกแบบ asynchronous (UC07 Main Flow 5; ASM-03, ASM-04)
- `GET /api/reports/negative-stock` ส่งกลับรายการวัตถุดิบที่มีการติดลบพร้อมสัญลักษณ์แจ้งเตือนและสถานะการตรวจสอบ (UC07 Alternative 5a; ASM-05)
- หน้า “จัดการสูตรเมนู”: ดึงข้อมูลเมนูและวัตถุดิบแล้วให้กรอกสัดส่วนและหน่วยนับในฟอร์มเดียวก่อนกดยืนยัน (UC07 Main Flow 1-4; ASM-01, ASM-02)
- หน้า “รายงานสต๊อกติดลบ”: แสดงข้อความเตือนและสถานะ Negative Stock Allowance เพื่อให้ผู้จัดการเห็นได้ทันที (UC07 Alternative 5a; ASM-05)

## 7. ลำดับงาน

1. สร้างโครงสร้างเมนู วัตถุดิบ และสูตรแบบ BOM พร้อมคอนแทร็กต์ใช้งาน `quantity` + `unit` เพื่อรองรับการผสมหน่วยนับต่างกันในสูตรเดียวกัน (UC07 Main Flow 1-2; ASM-01)
2. สร้าง API สำหรับบันทึกสูตร พร้อมโครงสร้าง `autoDeductEnabled` และ `menu_id` เพื่อให้เมนูมีสูตรเดียวตาม BOM และสวิตช์เปิด-ปิดแยกรายเมนู (UC07 Main Flow 1-4; ASM-02)
3. สร้างหน้าจอจัดการสูตรเมนูเพื่ออัปโหลด/แก้ไขวัตถุดิบและสัดส่วนต่อหนึ่งหน่วยบริโภค พร้อม validation ก่อนยืนยัน (UC07 Main Flow 2-4; ASM-01, ASM-02)
4. สร้างฐานข้อมูลการตัดสต๊อกและ InventoryDeductionJob เพื่อรองรับการประมวลผลแบบ asynchronous หลังชำระเงินและปิดบิลสำเร็จ (UC07 Main Flow 5; ASM-03)
5. สร้างกระบวนการคำนวณหักสต๊อกจากจำนวนสั่งจริง × สัดส่วนวัตถุดิบต่อหนึ่งหน่วยบริโภค พร้อมบันทึก InventoryLedger เพื่อใช้ตรวจสอบย้อนหลัง (UC07 Main Flow 5; ASM-04)
6. สร้างระบบ Negative Stock Allowance และรายงานแจ้งเตือนเมื่อสต๊อกติดลบ โดยยอมให้ขายต่อได้เพื่อความต่อเนื่องหน้าร้าน (UC07 Alternative 5a; ASM-05)
7. สร้าง dashboard / report สำหรับตรวจสอบสูตรและรายการตัดสต๊อกย้อนหลัง เพื่อให้ผู้จัดการเห็นสถานะข้อมูลและเหตุผลของสต๊อกติดลบ (UC07 Alternative 5a; ASM-05)
8. ดำเนินการทดสอบเชิงฟังก์ชันสำหรับการสร้างสูตร, การเปิด/ปิด auto-deduct, การตัดสต๊อกหลังชำระเงินสำเร็จ, การคำนวณจำนวนสั่งจริง, และการติดลบ/แจ้งเตือน (UC07 Main Flow 1-5, Alternative 5a; ASM-01-05)

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Questions ใน spec ขณะนี้ จึงไม่ต้องคัดลอกคำถามใด ๆ มาไว้ที่นี่

ส่วนที่ยังไม่สร้างจนกว่าจะมีคำตอบเพิ่มเติม:
- รูปแบบ payload และ retry policy ของ Inventory Deduction Engine ที่ใช้จริงในระบบผลิตภัณฑ์
- รายละเอียดของรายงานแจ้งเตือนสต๊อกติดลบว่าแสดงโครงสร้างอย่างไรบน dashboard และต้องมี action ใดบ้าง
- กรอบการจัดเก็บประวัติการตัดสต๊อกแบบละเอียดหากระบบต้องรองรับจำนวนคำสั่งซื้อที่สูงกว่า sandbox

ส่วนเหล่านี้ยังไม่สร้างจนกว่าทีมจะให้คำตอบเพิ่มเติม เพราะ spec ไม่ได้ระบุรายละเอียดเชิง interface หรือสถาปัตยกรรมการทำงานแบบละเอียดพอสำหรับการออกแบบระบบจริงโดยตรง

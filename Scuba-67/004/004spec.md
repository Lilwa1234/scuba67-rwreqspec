# Use Case Specification: UC04 - Monitor Real-time Payment & Log

* **Use Case ID:** UC04[cite: 5]
* **Use Case Name:** ตรวจสอบยอดเงินเข้าเรียลไทม์ (Monitor Real-time Payment & Log)[cite: 5]
* **Actor หลัก:** แคชเชียร์ (Cashier), เจ้าของร้าน / ผู้จัดการ (Owner / Manager)[cite: 5]
* **Pre-condition:** มีรายการชำระเงินผ่านการสแกนโอนเกิดขึ้นในระบบ[cite: 5]
* **Post-condition:** ผู้ใช้งานสามารถตรวจสอบหลักฐานรายการเงินเข้าที่จับคู่กับเลขออร์เดอร์และ Bank Ref ID ได้ เพื่อยืนยันสถานะชำระเงินและดำเนินการต่อตามเงื่อนไขของธุรกรรม[cite: 5]
* **Status:** Draft v2 | Updated: 2026-10-01

## Assumptions
* **ASM-01:** ระบบอัปเดตรายการเงินเข้าแบบเรียลไทม์ผ่าน WebSocket หรือ SSE โดยรายการใหม่จะปรากฏบน Transaction Feed ภายใน 1–2 วินาที โดยไม่ต้องกดรีเฟรชเอง
* **ASM-02:** หากไม่มียอดเข้าภายใน 3 นาที จะปรับสถานะเป็น "Pending" และแสดงแถบสีส้ม "รอยืนยันจากธนาคาร" เพื่อสื่อว่ารายการยังค้างในระบบ
* **ASM-03:** เมื่อ Payment Gateway ล่มหรือไม่ตอบสนอง ระบบจะแสดงแถบสีส้มสถานะ "รอยืนยันจากธนาคาร" (Pending) พร้อมปุ่ม "Copy Ref ID" เพื่อให้กดคัดลอกเพื่อนำไปติดตามกับ Call Center หรือ Payment Gateway ได้ทันที
* **ASM-04:** หน้าต่าง Transaction Feed จะแสดงควบคู่กันทั้งเลขออร์เดอร์ของระบบและ Bank Ref ID เพื่อความโปร่งใสในการตรวจสอบและติดตามธุรกรรม
* **ASM-05:** การจับคู่ข้อมูลใช้เลขออร์เดอร์ (Order ID) และ Bank Ref ID เป็นหลัก หากยอดเงินไม่ตรงหรือมีข้อผิดพลาด ระบบจะแยกรายการไปที่รายงาน Discrepancy Log เพื่อให้ตรวจสอบต่อไป
* **ASM-06:** แคชเชียร์สามารถดูการชำระเงินบนเครื่อง POS ส่วนเจ้าของร้านและผู้จัดการสามารถดูได้ทั้งบนเครื่อง POS และแอปพลิเคชันมือถือ
* **ASM-07:** Transaction Feed จะแสดงเป็นสลิปดิจิทัลเพื่อให้ผู้ใช้เทียบกับสลิปลูกค้า และสถานะชำระเงินจะถูกยืนยันและปิดบิลอัตโนมัติจากสัญญาณ Webhook ของระบบอยู่แล้ว
* **ASM-08:** รายการที่มีปัญหา เช่น ยอดเงินไม่ตรงหรือค้างในระบบ จะถูกนำเข้าสู่รายงาน "Discrepancy / Pending Log" เพื่อให้ทีมติดตามและประสานกับผู้ให้บริการ Gateway ทันที

## Main Flow (ลำดับขั้นตอนปกติ)
1. ผู้ใช้งานเปิดหน้าต่าง "ประวัติธุรกรรม / ฟีดเงินเข้า (Transaction Feed)" บนเครื่อง POS หรือแอปพลิเคชันมือถือ[cite: 5]
2. ระบบเชื่อมต่อแบบเรียลไทม์ผ่าน WebSocket หรือ SSE และแสดงรายการเงินเข้าเรียงตามเวลาล่าสุดภายใน 1–2 วินาที โดยระบุเลขออร์เดอร์, ยอดเงิน, เวลาที่โอน, และ Bank Ref ID[cite: 5]
3. ผู้ใช้งานตรวจสอบความถูกต้องโดยเทียบรายการกับหลักฐานของลูกค้า และยืนยันว่าเลขออร์เดอร์และ Bank Ref ID ตรงกับธุรกรรมที่เกิดขึ้น[cite: 5]
4. เมื่อระบบได้รับสัญญาณยืนยันจาก Webhook แล้ว สถานะชำระเงินจะถูกยืนยันและปิดบิลอัตโนมัติ โดยประวัติธุรกรรมปรับให้สอดคล้องกับสลิปดิจิทัลที่แสดงอยู่[cite: 5]

## Alternative / Exception Flows (ขั้นตอนทางเลือก / กรณีข้อผิดพลาด)
* **2a. ยอดเงินไม่เข้าหรือสถานะค้างในระบบ:** หากไม่มียอดเข้าภายใน 3 นาที ระบบจะแสดงแถบสีส้ม "รอยืนยันจากธนาคาร" (Pending) พร้อมปุ่ม "Copy Ref ID" เพื่อใช้ติดตามกับ Call Center หรือ Payment Gateway ได้ทันที[cite: 5]
* **2b. Gateway ล่มหรือไม่ตอบสนอง:** ระบบแสดงสถานะ "รอยืนยันจากธนาคาร" (Pending) แบบสีส้ม และให้ผู้ใช้กดคัดลอก Bank Ref ID เพื่อใช้เป็นข้อมูลอ้างอิงในการติดตามสถานะกับผู้ให้บริการที่เกี่ยวข้อง[cite: 5]
* **3a. ยอดเงินไม่ตรงหรือมีข้อผิดพลาด:** ระบบจะแยกรายการดังกล่าวไปยังรายงาน "Discrepancy / Pending Log" พร้อมระบุว่ารายการอยู่ระหว่างการตรวจสอบกับผู้ให้บริการ Gateway[cite: 5]

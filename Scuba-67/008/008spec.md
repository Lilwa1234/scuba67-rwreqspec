# Use Case Specification: UC08 - Record Waste & Staff Meals

* **Use Case ID:** UC08[cite: 5]
* **Use Case Name:** บันทึกของเสียและอาหารพนักงาน (Record Waste & Staff Meals)[cite: 5]
* **Actor หลัก:** แคชเชียร์ (Cashier), เจ้าของร้าน / ผู้จัดการ (Owner / Manager)[cite: 5]
* **Status:** Draft v2
* **Updated:** 2026-10-03
* **Pre-condition:** เกิดของเสีย ชงผิด หก หรือพนักงานทำเครื่องดื่มรับประทานเอง[cite: 5]
* **Post-condition:** สต๊อกวัตถุดิบถูกตัดออก และบันทึกต้นทุนเป็นค่าใช้จ่ายภายใน ไม่กระทบยอดขายจริง[cite: 5]

## Assumptions
* **ASM-01:** หน้าจอและฟังก์ชันเดียวกันคือ "บันทึกตัดสต๊อกภายใน / ของเสีย (Internal Waste Log)" และระบบจะแยกประเภทด้วยดรอปดาวน์เหตุผล เช่น ชงผิด, หมดอายุ, สวัสดิการพนักงาน
* **ASM-02:** พนักงานทั่วไปหรือแคชเชียร์สามารถทำรายการได้ แต่ระบบจะไม่อนุญาตให้กดยืนยันตัดสต๊อก หากยังไม่ได้กรอกรหัส PIN ของผู้จัดการเพื่ออนุมัติ
* **ASM-03:** การบันทึกต้องระบุรายการเมนูหรือวัตถุดิบ, เหตุผลในการตัดยอด, และรหัส PIN ของผู้จัดการเพื่ออนุมัติรายการก่อนบันทึกเสร็จสิ้น
* **ASM-04:** การบันทึก "สวัสดิการพนักงาน" จะจัดเก็บเป็นค่าใช้จ่ายภายใน (Expense / Loss) และตัดสต๊อกตามสูตร โดยไม่นำไปคำนวณเป็นยอดขายหน้าร้าน (Gross Sales)
* **ASM-05:** หากรหัส PIN ของผู้จัดการไม่ถูกต้องหรือไม่ได้รับอนุมัติ ระบบจะไม่อนุญาตให้กดยืนยันและจะไม่ตัดยอดสต๊อกตามเงื่อนไข Role-based Control

## Main Flow (ลำดับขั้นตอนปกติ)
1. ผู้ใช้งานเลือกฟังก์ชัน "บันทึกตัดสต๊อกภายใน / ของเสีย (Internal Waste Log)" บนระบบ POS และเลือกเหตุผลจากดรอปดาวน์ เช่น ชงผิด, หมดอายุ, สวัสดิการพนักงาน[cite: 5]
2. เลือกรายการเมนูหรือวัตถุดิบที่เสียหาย หรือนำไปใช้ภายใน[cite: 5]
3. ระบุเหตุผลในการตัดยอด และกรอกรหัส PIN ของผู้จัดการเพื่ออนุมัติรายการก่อนกดยืนยัน[cite: 5]
4. กดยืนยันการตัดสต๊อก[cite: 5]
5. ระบบหักยอดคงเหลือของวัตถุดิบ, บันทึกข้อมูลลงรายงานต้นทุนสูญเสีย (Loss & Waste Report), และจัดเก็บเป็นค่าใช้จ่ายภายใน โดยไม่กระทบยอดขายจริง[cite: 5]

## Alternative / Exception Flows (ขั้นตอนทางเลือก / กรณีข้อผิดพลาด)
* **1a. กำหนดสิทธิ์การตัดของเสีย:** หากเปิดระบบรักษาความปลอดภัย ผู้ใช้งานจะต้องกรอกรหัส PIN ของผู้จัดการก่อนกดยืนยันการตัดของเสีย หาก PIN ไม่ถูกต้องหรือไม่ได้รับอนุมัติ ระบบจะปฏิเสธการยืนยันและไม่ตัดยอดสต๊อกตาม Role-based Control
* **1b. รายการหรือเหตุผลไม่ถูกต้อง:** หากเลือกรายการหรือเหตุผลไม่ครบถ้วน ระบบจะไม่อนุญาตให้กดยืนยันและต้องกลับไปแก้ไขข้อมูลให้ครบก่อนบันทึก

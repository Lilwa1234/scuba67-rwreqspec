# Use Case Specification: UC10 - Generate Sales & Settlement Report

* **Use Case ID:** UC10[cite: 5]
* **Use Case Name:** ออกรายงานยอดขายและกระทบยอด (Generate Sales & Settlement Report)[cite: 5]
* **Status:** Draft v2
* **วันที่อัปเดต:** 2026-10-03
* **Actor หลัก:** เจ้าของร้าน / ผู้จัดการ (Owner / Manager)[cite: 5]
* **Pre-condition:** มีการทำรายการขายและทำการปิดกะประจำวันเรียบร้อยแล้ว และผู้ใช้สามารถเลือกช่วงเวลาได้ผ่าน Date Range Picker โดยตรงสำหรับรายวัน รายสัปดาห์ หรือรายเดือน[cite: 5]
* **Post-condition:** รายงานสรุปยอดขาย ยอดรับเงินโอน และค่าธรรมเนียมถูกสร้างขึ้นและพร้อมส่งออก พร้อมแยกข้อมูลที่ไม่ตรงกับ Statement ธนาคารไปยังรายงาน "Discrepancy / Pending Log" ตามเงื่อนไขที่กำหนด[cite: 5]

## Main Flow (ลำดับขั้นตอนปกติ)
1. เจ้าของร้านเปิดหน้าต่าง "รายงานยอดขายและการเงิน" บนระบบ[cite: 5]
2. ระบุช่วงเวลาที่ต้องการดูข้อมูลผ่าน Date Range Picker ได้โดยตรง โดยใช้เงื่อนไขว่าต้องเป็นรายการขายที่ทำการปิดกะประจำวันเรียบร้อยแล้ว และสามารถเลือกได้ทั้งรายวัน รายสัปดาห์ หรือรายเดือน[cite: 5]
3. ระบบประมวลผลผ่าน Reporting Aggregation API และแสดงยอดขายรวม จำแนกตามช่องทางชำระเงินหลัก 2 ช่องทาง ได้แก่ เงินสดและ QR Code, ค่าธรรมเนียมระบบ, ยอดรับสุทธิ, และยอดตัดสต๊อก โดยใช้สูตร `ยอดขายเงินสด + ยอด QR Code - ค่าธรรมเนียมระบบ = ยอดรับสุทธิ` และต้องคำนวณถูกต้อง 100% ปราศจากข้อผิดพลาดทศนิยม[cite: 5]
4. เจ้าของร้านกดปุ่มส่งออกรายงานในรูปแบบไฟล์ PDF หรือ Excel (.xlsx) แบบตารางมาตรฐานสำหรับงานบัญชีที่อ่านง่าย โดยมีหัวข้อสรุปยอดขายรวม (Gross Sales), แยกช่องทางชำระเงิน, ค่าธรรมเนียม, ยอดสุทธิ (Net Sales) และยอดตัดสต๊อก ซึ่งตัวเลขต้องถูกต้องตรงกับหน้าจอ Dashboard[cite: 5]

## Alternative / Exception Flows (ขั้นตอนทางเลือก / กรณีข้อผิดพลาด)
* **3a. ยอดเงินไม่ตรงกับ Statement ธนาคาร:** เจ้าของร้านสามารถกดดูรายงาน "Discrepancy / Pending Log" เพื่อดูรายการที่อยู่ระหว่างการตรวจสอบของ Gateway ได้ทันที ระบบจะไม่ลบหรือยกเลิกรายการ แต่จะแยกข้อมูลไปแสดงภายใต้รายงานดังกล่าวเพื่อให้เจ้าของร้านตรวจสอบความค้างหรือรายการที่รอการยืนยันกับ Payment Gateway[cite: 5]

## Assumptions (ข้อสมมติฐานจากคำตอบของทีม)
- **ASM-01:** ผู้ใช้สามารถเลือกช่วงเวลาได้ผ่าน Date Range Picker แบบรายวัน รายสัปดาห์ หรือรายเดือน โดยมีเงื่อนไขเบื้องต้นว่าต้องเป็นรายการขายที่ทำการปิดกะประจำวันเรียบร้อยแล้ว (Q1)
- **ASM-02:** ระบบประมวลผลยอดรับสุทธิผ่าน Reporting Aggregation API โดยใช้สูตร `ยอดขายเงินสด + ยอด QR Code - ค่าธรรมเนียมระบบ = ยอดรับสุทธิ` และต้องคำนวณถูกต้อง 100% โดยไม่มีความคลาดเคลื่อนทศนิยม (Q2)
- **ASM-03:** “ยอดตัดสต๊อก” หมายถึงปริมาณและรายการวัตถุดิบที่ถูกหักลบออกจากคลังจริงตามสูตร (BOM) จากยอดรายการขายที่สำเร็จในรอบเวลานั้น (Q3)
- **ASM-04:** รายงานจะแยกช่องทางชำระเงินออกเป็น 2 ช่องทางหลัก ได้แก่ ยอดชำระด้วยเงินสด และยอดสแกนจ่ายผ่าน QR Code เท่านั้น (Q4)
- **ASM-05:** ไฟล์ส่งออก PDF และ Excel (.xlsx) จะอยู่ในรูปแบบตารางมาตรฐานสำหรับงานบัญชีที่อ่านง่าย พร้อมหัวข้อสรุปยอดขายรวม (Gross Sales), แยกช่องทางชำระเงิน, ค่าธรรมเนียม, ยอดสุทธิ (Net Sales), และยอดตัดสต๊อก โดยตัวเลขต้องตรงกับหน้าจอ Dashboard (Q5)
- **ASM-06:** หากยอดเงินไม่ตรงกับ Statement ธนาคาร ระบบจะไม่ลบหรือยกเลิกรายการ แต่จะแยกข้อมูลไปแสดงในรายงาน "Discrepancy / Pending Log" ทันที เพื่อให้เจ้าของร้านตรวจสอบรายการที่ติดค้างหรืออยู่ระหว่างการยืนยันกับ Payment Gateway (Q6)

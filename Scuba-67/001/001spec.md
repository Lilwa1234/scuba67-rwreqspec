# Use Case Specification: UC01 - Manage Sales Order

* **Use Case ID:** UC01[cite: 5]
* **Use Case Name:** จัดการคำสั่งซื้อหน้าร้าน (Manage Sales Order)[cite: 5]
* **Status:** Draft v2
* **วันที่อัปเดต:** 2026-10-01
* **Actor หลัก:** แคชเชียร์ / พนักงานหน้าร้าน (Cashier)[cite: 5]
* **Actor รอง:** ลูกค้า (Customer)
* **Pre-condition:** แคชเชียร์เข้าสู่ระบบและทำการเปิดกะการขายเรียบร้อยแล้ว[cite: 5]
* **Post-condition:** คำสั่งซื้อถูกสร้างในสถานะ "รอชำระเงิน" (Pending Payment) ยอดเงินรวมถูกคำนวณ และพร้อมส่งพิมพ์ใบแจ้งงานครัว (KOT) พร้อมส่งยอดไปยังหน้าจอรับเงิน[cite: 5]

## Main Flow (ลำดับขั้นตอนปกติ)
1. แคชเชียร์เลือกหมวดหมู่สินค้าและเพิ่มรายการเมนูลงในตะกร้าตามที่ลูกค้าสั่ง โดยเพิ่มได้หลายเมนู หลายจำนวน และเพิ่มเมนูเดียวกันซ้ำโดยระบุตัวเลือกเสริมต่างกันได้ในบิลเดียว[cite: 5]
2. แคชเชียร์เลือกตัวเลือกเสริม (Modifiers) ของแต่ละรายการ โดยต้องเลือกชนิดร้อน/เย็น/ปั่นหนึ่งอย่างและขนาดแก้วหนึ่งขนาด ระดับความหวานมีค่าเริ่มต้นให้ และท็อปปิ้งสามารถเว้นว่างได้[cite: 5]
3. ระบบคำนวณราคาต่อหน่วยและยอดรวมสะสมแบบเรียลไทม์บนจอ POS เพื่อให้แคชเชียร์ทวนยอด และแสดงยอดบนหน้าจอฝั่งลูกค้าในขั้นตอนคิดเงิน[cite: 5]
4. เมื่อมีสินค้าในตะกร้าอย่างน้อยหนึ่งรายการและเลือกตัวเลือกที่บังคับครบแล้ว แคชเชียร์ทวนรายการและยอดรวมกับลูกค้า จากนั้นกดยืนยันคำสั่งซื้อ[cite: 5]

## Alternative / Exception Flows (ขั้นตอนทางเลือก / กรณีข้อผิดพลาด)
* **1a. แก้ไขรายการก่อนยืนยัน:** แคชเชียร์สามารถเพิ่มหรือลดจำนวน เปลี่ยนตัวเลือกเสริม หรือลบรายการในตะกร้าได้ไม่จำกัดครั้งแบบเรียลไทม์จนกว่าจะยืนยันบิล โดยไม่ต้องใช้ PIN ผู้จัดการ ระบบคำนวณยอดรวมใหม่หลังการแก้ไข และถือว่าการลบหรือลดรายการสำเร็จเมื่อยอดรวมปรับลดลงถูกต้องครบถ้วน[cite: 5]
* **2a. วัตถุดิบเสริมหมดสต๊อก:** ระบบปิดปุ่มตัวเลือกนั้นเป็นสีเทา แสดงป้าย "หมด" และล็อกไม่ให้เลือก

## Assumptions (ข้อสมมติฐานจากคำตอบของทีม)
- **ASM-01:** ก่อนยืนยันต้องเปิดกะแล้ว มีสินค้าในตะกร้าอย่างน้อยหนึ่งรายการ เลือกตัวเลือกบังคับครบ และทวนยอดกับลูกค้า (Q1)
- **ASM-02:** แก้ไขตะกร้าได้ไม่จำกัดครั้งจนกว่าจะยืนยัน ทั้งการเพิ่ม/ลดจำนวน เปลี่ยนตัวเลือกเสริม และลบรายการ (Q2)
- **ASM-03:** ตัวเลือกที่หมดหมายถึงวัตถุดิบเสริมหมดสต๊อก และต้องปิดปุ่มเป็นสีเทา แสดงป้าย "หมด" และไม่ให้เลือก (Q3)
- **ASM-04:** หลังยืนยัน คำสั่งซื้ออยู่ในสถานะ "รอชำระเงิน" (Pending Payment) พร้อมส่งพิมพ์ KOT และส่งยอดไปหน้าจอรับเงิน (Q4)
- **ASM-05:** ลบหรือลดรายการได้ทันทีโดยไม่ต้องใช้ PIN ผู้จัดการ และสำเร็จเมื่อยอดรวมปรับลดลงถูกต้องครบถ้วน (Q5)
- **ASM-06:** ต้องเลือกชนิดร้อน/เย็น/ปั่นหนึ่งอย่างและขนาดแก้วหนึ่งขนาด ระดับความหวานมีค่าเริ่มต้น และท็อปปิ้งไม่บังคับ (Q6)
- **ASM-07:** หนึ่งบิลมีได้หลายเมนู หลายจำนวน และเมนูเดียวกันซ้ำได้หากระบุตัวเลือกเสริมต่างกัน (Q7)
- **ASM-08:** ระบบแสดงยอดรวมที่คำนวณใหม่แบบเรียลไทม์บนจอ POS และแสดงยอดบนหน้าจอลูกค้าในขั้นตอนคิดเงิน (Q8)
